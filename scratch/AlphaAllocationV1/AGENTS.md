# AlphaAllocationV1 research instructions

Follow the [repository-wide instructions](../../AGENTS.md). Prioritize US Alpha-HRP V1 research before resuming V2. Keep V1 experiment code, configs, and outputs in this folder. Reuse production math and existing evidence through read-only access. Keep experimental writes away from production model buckets, `current` pointers, sticky history, scheduled jobs, and broker accounts. Any rollout is a separate task.

- Start with the [README](README.md) and [saved research recommendation](V1_RESEARCH_RECOMMENDATION.md). Use the prior 27 experiments to inform candidate selection and treat their evaluation periods as exploratory.
- Name each checkpoint and training recipe precisely. Record the deployed checkpoint ID and data cutoff where known. Label actual broker performance, deployed-checkpoint reconstruction, and causally retrained baselines explicitly. Identify unavailable inputs and stop short of claiming replay parity where evidence is missing.
- Reconcile scores, selected names, HRP target weights, fills, and NAV on archived weeks before interpreting portfolio backtests. Use the data cutoff and prior holdings that applied to each rebalance. Report where simulated fills or accounting differ from Alpaca.
- Run causal walk-forward tests. Use membership and observations available at the historical cutoff, keep label windows within their folds, and fit preprocessing and tune models on training and validation only. Disclose data coverage, survivorship bias, corporate-action treatment, and the distinction between verified zero news and missing coverage. Apply exclusions using only data available when the rule would run.
- Begin with the four arms in the README. Hold selection, HRP, and execution assumptions common when comparing forecasts. Pair results on common weeks, document omitted dates and missing holdings, and let holdings and cash evolve separately in each arm. Keep the prediction label and the executable holding period explicit.
- Before confirmation, record the candidate and incumbent, date range or prospective duration, primary metric, minimum meaningful effect, risk tolerances, tests, block length and sensitivity checks, comparison family, and decision rule. Set the family significance level to 5%. Use paired weekly net return differences against SPY and the incumbent, with a block bootstrap and Holm adjustment as described in the README. Use ranking and prediction error as diagnostics. Report drawdown, turnover, costs, weekly uncertainty, and seed sensitivity. Label exploratory and inconclusive outcomes accordingly.
- Save the code revision, exact run command, data manifest, feature formulas, split boundaries, model configuration, seeds, checkpoint IDs, weekly return series, and results, including null and unfavorable ones. Store credentials and sensitive broker exports outside tracked files. Preserve the frozen evaluation record if a follow-up experiment changes the protocol.
- Archive finished charts under `figures/`, using a subfolder named for the experiment or report. Embed figures with relative paths in the relevant Markdown report and link the report from the V1 README. Keep working outputs and raw evidence under the ignored `data/` directory. When a report contains many charts, link to a gallery in the report.
